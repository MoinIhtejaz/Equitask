# Equitask

Equitask is a full-stack web app for university group assignments that prioritizes fair workload distribution, task effort voting, availability-aware assignment, accountability, and team analytics.

The app supports two clean operating modes:

- Demo mode (works instantly with seeded local data, no Supabase required)
- Supabase mode (real sign-up/sign-in and persisted data once Supabase is wired)

## Project Overview

Equitask solves group-project imbalance by making effort estimation and assignment transparent:

- Story point voting happens before assignment
- Official effort is based on team average votes
- Workload fairness is continuously measured
- Overload and overdue risk are surfaced early
- Analytics shows contribution and progress trends

## Key Features

- Landing page with product positioning and CTA flow
- Demo login (always available)
- Supabase-ready sign-up and sign-in (email/password)
- Team Hub for creating teams, joining by team code, and switching active team
- Dashboard with summary cards, fairness score, activity feed, notifications, progress chart, and member cards
- Scrum board with status updates, assignment updates, and task creation panel
- Task detail page with voting, comments, assignment recommendations, and activity log
- Dedicated voting center for planning-poker style estimation
- Member profile page with timetable-style weekly availability
- Analytics page with Recharts visualizations
- Settings page for mode/session visibility and switching

## Supabase Setup

### 1. Create a Supabase Project

Create a project in Supabase and wait for it to initialize.

### 2. Enable Email/Password Auth

In Supabase Dashboard:

- Go to `Authentication` -> `Providers`
- Enable `Email`
- Enable `Email + Password` sign-in
- Optional: disable email confirmation for faster dev testing

### 3. Add Environment Variables

Add these to your local environment and Vercel project settings:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

### 4. Run SQL in Supabase

- Go to `Supabase Dashboard` -> `SQL Editor`
- Create a new query
- Paste the full SQL from the section **SQL to Run in Supabase**
- Run it

### 5. Start App and Test Auth

- Start app: `npm run dev`
- Open `/sign-up` and create an account
- During sign-up, either create a new team or join with a team code
- Then sign in at `/sign-in`
- If the user has a team membership, login redirects to `/dashboard`
- If no team membership exists, login redirects to `/teams` (Team Hub)
- Workspace, board, voting, and analytics all load from the active team in session

### 6. Switching from Demo Mode to Supabase Mode

- Demo mode stays available at all times
- Supabase mode is used when:
  - env vars are configured
  - user signs in through Supabase form
- Team context is saved in session (`teamId`) so users return to their team workspace directly
- You can switch back to demo mode from `Settings`

);

  id text primary key default ('vote-' || gen_random_uuid()::text),

  vote_value int not null check (vote_value in (1, 2, 3, 5, 8, 13)),
  created_at timestamptz not null default now(),
  unique (task_id, member_id)
);

-- Comments
create table if not exists public.comments (
  id text primary key default ('comment-' || gen_random_uuid()::text),
  task_id text not null references public.tasks(id) on delete cascade,
  member_id text not null references public.profiles(id) on delete cascade,
  body text not null,
  created_at timestamptz not null default now()
);

-- Notifications
create table if not exists public.notifications (
  id text primary key default ('notif-' || gen_random_uuid()::text),
  team_id text not null references public.teams(id) on delete cascade,
  type text not null check (type in ('vote_needed', 'task_overdue', 'task_assigned', 'member_overloaded', 'vote_disagreement', 'deadline_approaching')),
  message text not null,
  task_id text references public.tasks(id) on delete set null,
  member_id text references public.profiles(id) on delete set null,
  is_read boolean not null default false,
  severity text not null check (severity in ('info', 'warning', 'critical')),
  created_at timestamptz not null default now()

-- Indexes

create index if not exists idx_tasks_team_status on public.tasks(team_id, status);
create index if not exists idx_tasks_assignee on public.tasks(assignee_id);
create index if not exists idx_tasks_due_date on public.tasks(due_date);
create index if not exists idx_votes_task on public.task_votes(task_id);
create index if not exists idx_comments_task on public.comments(task_id);
create index if not exists idx_notifications_team_created on public.notifications(team_id, created_at desc);

before update on public.tasks
for each row

### Demo Mode Architecture

- Session mode: `demo`
- Data source: in-memory seeded provider (`demoProvider`)
- No Supabase dependency
- Demo login available from landing/sign-in

### Supabase Mode Architecture

- Session mode: `supabase`
- Session stores active team context (`teamId`, team/project metadata)
- Data source: Supabase provider (`supabaseProvider`)
- Auth: Supabase email/password through API routes
- Team Hub supports create/join/switch workflows
- Workspace reads/writes through provider abstraction

### Data Abstraction and Service Layer

The app uses:

- Provider layer:
  - `demoProvider`
  - `supabaseProvider`
- Service layer:
  - `authService`
  - `taskService`
  - `voteService`
  - `memberService`
  - `analyticsService`
  - `fairnessService`
  - `notificationService`
  - `teamService`
  - `workspaceService`

This avoids business-logic duplication and lets the same UI run against either data source.

## Fairness Score Logic

Fairness score (0-100) is calculated from:

- Balance of assigned story points
- Balance of completed story points
- Overdue task penalty
- Voting compliance before assignment
- Overload penalty when one member carries too much active effort

The score and breakdown are visible in dashboard and analytics.

## Voting Logic

- Team members vote using `1, 2, 3, 5, 8, 13`
- Votes are stored per task/member
- Average vote is computed
- When all members vote, task voting closes and average becomes official story points
- Disagreement range (`max - min`) is surfaced
- Strong disagreement warnings appear when range is high

## Troubleshooting

### Supabase sign-in fails with invalid login

- Verify email/password provider is enabled.
- If email confirmation is enabled, confirm user email first.

### App stays in demo mode

- Ensure env vars are set and app restarted.
- Use `/sign-in` form (not Demo Login) to create a Supabase session.

### SQL errors on policy creation

- Run SQL in order as provided.
- Ensure tables/functions exist before policies.

### Empty analytics in Supabase mode

- Create/sign in user first.
- Ensure user has joined or created a team (`/teams`).
- Create tasks in `/board` and submit votes so charts have dataset to render.

### 401 responses from API routes

- Session cookie may be missing/expired.
- Sign in again via `/sign-in`.

### Redirected to /teams after sign-in

- The authenticated user has no row in `team_members`.
- Create a team in Team Hub or join using a valid team code.
- Team code is the `teams.id` value (format starts with `team-`).
